No modelo relacional, os dados ficam em tabelas (relações). Cada linha é uma tupla e cada coluna é um atributo com um tipo. Relacionamentos não são ponteiros: são valores iguais em colunas de tabelas diferentes. A tabela matriculas implementa o relacionamento muitos-para-muitos entre alunos e disciplinas.

4. Agregação: GROUP BY e HAVING

Funções de agregação (COUNT, SUM, AVG, MIN, MAX) resumem várias linhas numa só. Com GROUP BY, uma linha por grupo:

WHERE filtra linhas antes de agrupar; HAVING filtra grupos depois:

Ordem lógica de execução: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT. É por isso que um apelido criado no SELECT pode ser usado no ORDER BY, mas (em SQL padrão) não no WHERE.

Nunca rode UPDATE ou DELETE sem WHERE num banco de verdade, a não ser que queira mesmo alterar a tabela inteira. Transações garantem as propriedades ACID: Atomicidade (tudo ou nada), Consistência, Isolamento e Durabilidade.

8. Criando tabelas e índices

Um índice é uma estrutura auxiliar (uma árvore B+, parente da árvore de busca de Estruturas de Dados) que evita varrer a tabela inteira. Compare o plano de execução antes e depois:

Índices aceleram buscas, mas ocupam espaço e deixam INSERT/UPDATE mais lentos, porque o índice também precisa ser atualizado. Crie-os nas colunas usadas em filtros e junções frequentes.
