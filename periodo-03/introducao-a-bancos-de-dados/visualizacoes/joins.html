Introdução a Bancos de Dados

Como um JOIN funciona por dentro

Um JOIN combina linhas de duas tabelas que satisfazem uma condição. O algoritmo mais simples compara cada linha de A com cada linha de B. Escolha o tipo de JOIN e veja quais linhas entram no resultado e quais ficam de fora.

Resumo dos tipos

TipoEntra no resultadoPergunta típica
INNERsó os pares que casam"disciplinas e seus professores"
LEFTtudo de A (com NULL quando não casa)"todas as disciplinas, com professor se houver"
RIGHTtudo de B (com NULL quando não casa)o mesmo que LEFT com as tabelas trocadas
FULLtudo dos dois lados"compare as duas listas e mostre as diferenças"

Truque do anti-join: A LEFT JOIN B ... WHERE B.id IS NULL devolve as linhas de A sem par em B ("disciplinas sem professor", "clientes que nunca compraram"). Na página ao lado, o FTC (DCC129) é essa linha.

NULL não é igual a NULL. Em SQL, NULL = NULL dá desconhecido, não verdadeiro. Por isso uma disciplina sem professor nunca casa no JOIN, e para testar NULL se usa IS NULL, nunca = NULL.

Por que o banco não faz sempre o laço aninhado? Com 1 milhão de linhas em cada tabela seriam $10^{12}$ comparações. Com um índice (árvore B+) em B.id, cada linha de A encontra seu par em $O(\log n)$. O hash join monta uma tabela hash com B e varre A uma vez: $O(|A| + |B|)$. O otimizador escolhe sozinho: veja com EXPLAIN QUERY PLAN no tutorial de SQL.
