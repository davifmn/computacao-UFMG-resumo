Inferência de tipos: o compilador adivinha (e prova)

Em ML e Haskell você quase nunca escreve tipos, e mesmo assim o compilador recusa 1 + true antes de rodar. O algoritmo de Hindley-Milner dá a cada subexpressão uma variável de tipo, gera equações a partir do formato do código e as resolve por unificação. O resultado é o tipo mais geral possível.

Sintaxe: fn x => e, let x = e in e, let rec, if, + - * < =, (a, b), [], ::, hd tl null fst snd.

As regras, nó por nó

  • Constante: 3 : int, true : bool.
  • Função fn x => e: $x$ recebe uma variável nova $\alpha$; se o corpo tem tipo $\tau$, a função tem $\alpha \to \tau$.
  • Aplicação f a: se $f : \tau_f$ e $a : \tau_a$, cria $\beta$ nova e exige $\tau_f = \tau_a \to \beta$.
  • if: condição $= $ bool e os dois ramos com o mesmo tipo. Operadores: + exige int dos dois lados.
  • let x = e1 in e2: infere $e_1$ e generaliza as variáveis que não aparecem no ambiente: $\forall\alpha.\,\alpha \to \alpha$. Cada uso de $x$ em $e_2$ ganha uma cópia nova (instanciação).

Unificação

Para resolver $\tau_1 = \tau_2$: se um lado é variável $\alpha$, faça $\alpha := $ o outro (se $\alpha$ não aparecer dentro dele: o occurs check, que rejeita fn x => x x, cujo tipo teria que ser $\alpha = \alpha \to \beta$); se os dois são construtores, os nomes têm que ser iguais (int ≠ bool) e os argumentos são unificados um a um. É o mesmo algoritmo da unificação do Prolog (veja a outra página).

Polimorfismo do let × parâmetros

let id = fn x => x in (id 3, id true) tipa: id é generalizado. Mas (fn id => (id 3, id true)) (fn x => x) não: parâmetros de fn são monomórficos (um tipo só dentro do corpo). Permitir isso (polimorfismo de posto superior) torna a inferência indecidível; essa restrição é exatamente o que mantém Hindley-Milner completo e eficiente na prática.

Tipagem forte, estática, inferida. C é estática mas fraca (casts livres), Python é forte mas dinâmica (erros só em tempo de execução), ML é forte, estática e inferida. Java e C++ inferem tipos localmente (var, auto); Rust, Swift, Kotlin, TypeScript e Scala usam variações desta ideia.
