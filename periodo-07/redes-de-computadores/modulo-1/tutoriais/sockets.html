Programação em redes: sockets

O socket é a interface que o sistema operacional oferece às aplicações para usar a camada de transporte. Apareceu no UNIX de Berkeley (4.2BSD, 1983) e virou o padrão de fato: é assim que navegadores, servidores web e jogos conversam pela rede.

O ciclo de vida, passo a passo

Um servidor TCP de "eco" (devolve o texto em maiúsculas) e um cliente. Avance os passos e acompanhe a chamada em execução, o estado de cada lado e os segmentos que o TCP troca na rede.

O servidor executa as quatro primeiras nessa ordem: SOCKET → BIND → LISTEN → ACCEPT. O cliente faz SOCKET → CONNECT, sem BIND (o sistema escolhe uma porta efêmera, porque o endereço do cliente não importa para o servidor). Depois, ambos usam SEND/RECEIVE (ou os read/write comuns do UNIX) sobre uma conexão full-duplex.

Pontos que costumam cair

  • Por que SOCKET e BIND são separados? Alguns processos se importam com o endereço (um servidor web precisa estar sempre na porta 80), outros não (o cliente). Criar o socket não fixa endereço.
  • LISTEN não bloqueia; é o ACCEPT que espera. O parâmetro do LISTEN é o tamanho da fila de conexões pendentes: se ela encher, novos pedidos são descartados em silêncio.
  • ACCEPT devolve um descritor novo, com as mesmas propriedades do original. O servidor pode passar esse socket para uma thread ou processo filho (fork) e voltar a esperar no socket original: é assim que atende vários clientes ao mesmo tempo.
  • TCP é fluxo de bytes, não de mensagens: dois send podem chegar num único recv, e um send grande pode chegar em vários pedaços. A aplicação precisa delimitar as mensagens (tamanho no início, terminador como \n ou \0). No exemplo do livro, o cliente envia o nome do arquivo com o byte 0 final para o servidor saber onde ele termina.
  • Ordem dos bytes: números nos cabeçalhos (portas, IPs) vão na ordem de rede (big-endian). Em C, use htons/htonl ao preencher sockaddr_in e ntohs/ntohl ao ler, para funcionar em máquinas little-endian (x86) e big-endian.
  • SO_REUSEADDR (setsockopt): permite reiniciar o servidor na mesma porta logo depois de fechá-lo.
  • Sockets UDP (SOCK_DGRAM): sem conexão, sem LISTEN/ACCEPT. Usa-se sendto/recvfrom com o endereço do outro lado em cada datagrama. As mensagens preservam as fronteiras, mas podem se perder, duplicar ou chegar fora de ordem.
  • O socket é uma abstração do serviço de transporte: a mesma API serve para TCP (fluxo confiável), UDP (datagramas) e outros, como SCTP ou DCCP.
  • Uma conexão TCP é identificada pela quádrupla (IP de origem, porta de origem, IP de destino, porta de destino). Por isso vários clientes podem se conectar à mesma porta 5000 do servidor.

O mesmo servidor em C

É a mesma sequência de chamadas, com a estrutura sockaddr_in preenchida à mão:

#include <arpa/inet.h>
#include <netinet/in.h>
#include <string.h>
#include <sys/socket.h>
#include <unistd.h>

int main(void) {
    int s = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);        /* SOCKET */
    int on = 1;
    setsockopt(s, SOL_SOCKET, SO_REUSEADDR, &on, sizeof on);

    struct sockaddr_in end;
    memset(&end, 0, sizeof end);
    end.sin_family = AF_INET;
    end.sin_addr.s_addr = htonl(INADDR_ANY);                  /* qualquer interface */
    end.sin_port = htons(5000);                               /* ordem de rede! */
    bind(s, (struct sockaddr *) &end, sizeof end);            /* BIND */
    listen(s, 5);                                             /* LISTEN */

    for (;;) {
        int c = accept(s, NULL, NULL);                        /* ACCEPT: socket novo */
        char buf[1024];
        ssize_t n = recv(c, buf, sizeof buf, 0);              /* RECEIVE */
        for (ssize_t i = 0; i < n; i++)
            if (buf[i] >= 'a' && buf[i] <= 'z') buf[i] -= 32;
        send(c, buf, n, 0);                                   /* SEND */
        close(c);                                             /* CLOSE */
    }
}

Cliente: socket → preenche sockaddr_in com o IP do servidor (obtido por DNS com getaddrinfo/gethostbyname) e a porta → connect → send → recv em laço até receber tudo → close.
