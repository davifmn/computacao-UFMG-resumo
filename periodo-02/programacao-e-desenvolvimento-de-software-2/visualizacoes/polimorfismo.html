Polimorfismo por dentro: a vtable

Como f->area() sabe se deve calcular a área de um círculo ou de um retângulo, se f é só um Forma*? A resposta é um ponteiro escondido em cada objeto e uma tabela de funções por classe.

Os três pilares da orientação a objetos

  • Encapsulamento: dados privados e acesso só por métodos, para que a classe garanta suas próprias invariantes (ex.: um saldo nunca negativo).
  • Herança: class Circulo : public Forma significa que um círculo é uma forma e reaproveita a interface dela.
  • Polimorfismo: o mesmo código (f->area()) se comporta de forma diferente conforme o tipo real do objeto.

virtual faz toda a diferença

não virtuala de Forma (tipo do ponteiro)compilação (ligação estática)

virtual ... = 0nenhuma em Forma: a classe é abstrata e não pode ser instanciada—

Regra prática: se uma classe tem algum método virtual, o destrutor também deve ser virtual. Senão, delete por um ponteiro da base chama só o destrutor da base, e o que a filha alocou vaza.

Use override sempre que sobrescrever um método. Se você errar a assinatura (ex.: esquecer o const), o compilador avisa em vez de criar silenciosamente um método novo que nunca é chamado.

Em C++ moderno, prefira std::vector<std::unique_ptr<Forma>>: o delete acontece sozinho. O código completo está em codigo/formas/, e o tutorial de projeto C++ explica como organizá-lo.
