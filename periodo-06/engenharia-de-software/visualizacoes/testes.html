Tipos de teste

      
    
        
  • Unidade: uma função ou classe isolada, rápido, muitos. Integração: vários módulos juntos (com banco, com rede). Sistema / ponta a ponta: o sistema inteiro pela interface. A pirâmide de testes recomenda muitos de unidade e poucos de ponta a ponta, porque estes são lentos e frágeis.
    • 
        
  • Caixa-preta (pela especificação): partição em classes de equivalência e análise de valor-limite, como na suíte "Classes + fronteiras". Caixa-branca (pelo código): cobertura de comandos, ramos, condições, caminhos.
    • 
        
  • Dublês de teste (mocks, stubs, fakes) substituem dependências lentas ou não determinísticas, como banco de dados, rede e relógio.
    • 
      

      
O que cada métrica diz

      
Cobertura responde "que código os testes executam?", mas não "os testes verificam alguma coisa?". Um teste sem assert pode ter 100% de cobertura. Ela é útil ao contrário: código não coberto certamente não está testado. O teste de mutação introduz pequenos bugs plausíveis (trocar <= por <, and por or) e conta quantos a suíte detecta. Mutantes sobreviventes apontam exatamente o teste que falta, geralmente um valor-limite: para matar M3 é preciso um caso em que $a + b = c$.

      
TDD. No desenvolvimento dirigido por testes, o ciclo é vermelho (escreva um teste que falha), verde (o mínimo de código para passar), refatore. Os testes viram especificação executável e rede de segurança para refatorar. O código desta disciplina tem a mesma suíte em unittest.
