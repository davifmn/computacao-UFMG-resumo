Análise léxica: de caracteres a tokens

A primeira fase do compilador agrupa caracteres em tokens (identificadores, números, operadores) e joga fora espaços e comentários. Por dentro é um autômato finito determinístico, o mesmo de FTC, rodando com uma regra extra: sempre o maior casamento possível.

Do regex ao AFD

Cada tipo de token é descrito por uma expressão regular: ID = [A-Za-z_][A-Za-z0-9_]*, NUM = [0-9]+, OP = <= | < | == | …. Ferramentas como o lex/flex fazem o caminho de FTC: regex → AFN (Thompson) → AFD (subconjuntos) → AFD mínimo, e geram uma tabela de transições. O AFD acima foi escrito à mão, mas é o mesmo tipo de objeto.

Duas regras de desempate

  • Maior casamento (maximal munch): continue lendo enquanto houver transição e devolva o maior prefixo que parou num estado de aceitação. Por isso <= é um token só, e não < seguido de =; e iffy é um identificador, não if + fy.
  • Prioridade: se o mesmo lexema casa com duas regras (if é ID e é palavra reservada), vence a que vem primeiro. Na prática, o AFD reconhece identificadores e uma tabela de palavras reservadas decide depois, o que mantém o autômato pequeno.

O que o léxico não faz. Ele não sabe se os parênteses estão balanceados (isso exige uma pilha, ou seja, uma gramática livre de contexto, assunto da próxima página). E não sabe se uma variável foi declarada: isso é análise semântica, feita com a tabela de símbolos.
