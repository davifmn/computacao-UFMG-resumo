Busca sequencial × busca binária

Se o vetor está ordenado, cada comparação da busca binária elimina metade dos candidatos. Veja o intervalo de busca encolher.

Por que é tão rápida?

A cada iteração o tamanho do intervalo cai pela metade: $n \to n/2 \to n/4 \to \dots \to 1$. O número de passos é quantas vezes dá para dividir $n$ por 2, ou seja, $\lfloor \log_2 n \rfloor + 1$.

Cuidado com o pré-requisito: a busca binária só funciona se o vetor estiver ordenado. Ordenar custa pelo menos $O(n \log n)$, então só compensa se você for fazer várias buscas.

Bug clássico: meio = (ini + fim) / 2 pode estourar o int quando ini + fim passa de $2^{31}-1$. A forma segura é meio = ini + (fim - ini) / 2. Esse bug ficou escondido por anos na biblioteca padrão do Java.
